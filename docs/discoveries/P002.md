## Glob handling

Entries containing `**` are silently skipped — `Path::exists()` is undefined for glob patterns.
Rationale: AGENT_MAP legitimately uses globs like `src/parser/**` or `docs/Archive/**` to express "all files under this subtree." Checking existence of the literal string `src/parser/**` as a path would always fail. Skip is the SOUND behavior; a walkdir expansion would be PARTIAL (expansion depends on current working directory at invocation time).

Decision logged as Tầng 2 (local behavior, no cross-module impact). Documented in `never_default_read` scope note (SC2) in Debate Log.

## Anchor flexible match algorithm

1. Normalize both anchor (from YAML entry) and target text:
   - Lowercase
   - Replace `-` with space
   - Collapse consecutive whitespace (split_whitespace + join)
2. Markdown heading: regex `(?m)^#+\s+(.*)$` — capture heading text, normalize, compare.
3. Rust symbol: regex `(?m)^(?:pub\s+)?(?:fn|struct|enum|trait|impl)\s+(\w+)` — lowercase compare (Rust idents use underscores, not hyphens, so normalization step is just lowercase).

This covers the documented case study: `My-Section` anchor → `## My Section` heading.

## Exit code pattern (anyhow downcast vs error enum)

Pattern chosen: `std::process::exit()` inline (mirror of P001 `lane_check.rs` pattern), not `thiserror` enum downcast.

Rationale: P001 already established the `process::exit()` pattern. Consistency > novelty (Tầng 2 decision). `thiserror` enum would require main.rs to inspect error variants to map exit codes — adding coupling. The `process::exit()` approach keeps exit-code logic local to the subcmd.

The yaml parse error path uses `process::exit(2)` inside `map_err` closure (before `?`) — this ensures exit 2 is reached even though `serde_yaml::Error` wraps into anyhow. The `?` after the closure is unreachable but satisfies the type system.
