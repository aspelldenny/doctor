## Refactor scope: execute/run split

All 4 subcmds extracted `pub fn execute(args: Args) -> Result<RunOutput>`:

- **lane_check**: 2 `std::process::exit()` calls → `out.exit_code = 2` (missing Lane) and `out.exit_code = 1` (budget exceeded). All `println!`/`eprintln!` → `out.stdout.push_str()` / `out.stderr.push_str()`. `run()` thin wrapper: call execute + print + exit(N).
- **validate_map**: yaml parse error `std::process::exit(2)` → `out.exit_code = 2; return Ok(out)`. drift list `std::process::exit(1)` → `out.exit_code = 1`. `run()` thin wrapper.
- **rotate_check**: toml parse error had `std::process::exit(2)` inside `resolve_config` — refactored to `out.exit_code = 2` via `&mut RunOutput` param. After `resolve_config`, early return if `out.exit_code != 0`. `worst: u8` → `out.exit_code = worst`. `run()` thin wrapper.
- **runtime_scan**: was already returning `Err(anyhow!("..."))` for leaks (which main.rs would map to exit 1 via `?`). Refactored: leaks → `out.exit_code = 1; out.stderr += ...`. Clean → `out.exit_code = 0`. `run()` thin wrapper.

**RunOutput struct location:** `src/cli/mod.rs` (shared, B pattern) — DRY, MCP module imports from `crate::cli::RunOutput`. Correct choice.

**Regression:** 27/27 existing tests pass after refactor — zero behavioral change in CLI paths.

## rmcp 1.7.0 API notes

**Struct pattern:** Advisory-inbox uses unit struct `AdvisoryInboxService;` (no fields). rmcp tests show alternate pattern with explicit `tool_router: ToolRouter<Self>` field + `#[tool_router(router = tool_router)]`. Chose unit struct (advisory-inbox precedent) — simpler, no field needed.

**Tool fn signature:** `fn name(&self, Parameters(p): Parameters<InputStruct>) -> Result<CallToolResult, ErrorData>` — destructuring in parameter (`Parameters(p)` not `params: Parameters<T>`) matches advisory-inbox pattern. This compiles without issue.

**CallToolResult API:**
- `CallToolResult::success(vec![Content::text(text)])` → sets `is_error: Some(false)`
- `CallToolResult::error(vec![Content::text(text)])` → sets `is_error: Some(true)`
- Both methods exist in rmcp 1.7.0 — no struct literal needed.

**ServerInfo API:** `ServerInfo::new(capabilities).with_server_info(Implementation::new(name, version))` — matches advisory-inbox exactly. `from_build_env()` avoided (reads rmcp's own crate name, not ours — P011 retro).

**Transport import path:** `rmcp::transport::io::stdio` (not `rmcp::transport::stdio`). Advisory-inbox serve.rs confirms.

**`serve()` error mapping:** rmcp returns a type that doesn't implement `std::error::Error` directly. Used `.map_err(|e| anyhow::anyhow!("...: {}", e))` on both `.serve()` and `.waiting()` calls to bridge to anyhow.

4. **MCP JSON field `isError` (camelCase):** rmcp serializes `is_error` field as `"isError"` (serde rename_all camelCase). Test `lane_check_tool_call_happy_path` correctly reads `result.get("isError")`.
