## File-missing skip behavior (vs P002 PATH_MISSING)

P003: file missing → **skip, no drift**. Rationale: rotate targets (`docs/CHANGELOG.md`) may not yet exist in a new repo; that's valid, not an error. Counter-example: P002 validate-map PATH_MISSING is an *error* because AGENT_MAP entry explicitly declares the file should exist.

Edge case: empty file → `"".lines().count() = 0` → clean (below any soft cap). File with only trailing newline → `lines()` does not emit empty final element → count may be 1 less than raw line count. Documented here; acceptable for §6 intent (over-cap detection).

---

## Per-field fallback vs all-or-nothing

Decision: per-field fallback. If `.sos-stack.toml` has `[rotate]` with only `soft = 500` and no `hard` or `files`, the missing fields fall back to defaults individually. This gives partial config override flexibility without requiring complete spec.

## Per-file cap deferral (v1 flat schema)

v1 uses flat `soft`/`hard` caps applying uniformly to all files in the list. Per-file cap (e.g., `[[rotate.files]] path="..." hard=2000`) deferred to v2 if needed. Discovery note: the flat schema covers the §6 doctrine requirement; per-file tuning is enhancement.

## Exit code pattern

Pattern chosen: `std::process::exit(N)` for known severity codes (matching P001/P002 pattern). `anyhow::Result<()>` propagation from `run()` is used only for I/O errors (cannot read file). Toml parse error uses explicit `std::process::exit(2)` after `eprintln!` to match the §6 spec (toml error = hard block).

The `run()` function itself doesn't return `Err(...)` for severity codes — it calls `std::process::exit` directly, consistent with P001 lane_check.rs pattern.
