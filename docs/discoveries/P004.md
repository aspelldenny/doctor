## Implementation Decisions

### sk-* / sk-ant-* overlap handling

Phiếu notes overlap: `sk-[A-Za-z0-9]{32,}` would also match the beginning of `sk-ant-XXXX` tokens. Pattern ordering in PATTERNS array: `anthropic_key` placed BEFORE `openai_key`. Effect: a `sk-ant-*` token gets reported as `anthropic_key` on first match; the regex loop continues and may also report `openai_key` for same line (dual-hit). Worker chose **accept dual-hit** (simpler, no loss) as phiếu recommends. Test #4 and #6 confirm `anthropic_key` fires; no additional assertion needed on suppression.

### .env* glob strategy

Used `std::fs::read_dir(repo_root)` + filter `name.to_string_lossy().starts_with(".env")` + `file_type().is_file()`. walkdir NOT used (reserved for future recursive case — Cargo.toml dep already present). Per anchor #4 fallback note: if `.env` ever lives in a subfolder, upgrade path is `walkdir::WalkDir::new().max_depth(1)`.

### --include-home default false

Privacy-sensitive: scanning `~/.ssh/config`, `~/.gitconfig`, `~/.netrc` reads credentials beyond repo scope. Must be explicit `--include-home` opt-in. Constraint #2.

### Output sanitize

`format!("{}:{}: {}", path, line_num, pattern_name)` — matched content (the actual token value) is NOT included. Test #6 (`stderr_no_secret_content`) verifies that stderr does not contain the fake token body.

### V2 O1.1 ACCEPT: OpenAI pattern

`sk-[A-Za-z0-9]{32,}` catches legacy classic sk-* format only. `sk-proj-*` (dash in body after `sk-`) is NOT caught by this pattern — dash breaks `[A-Za-z0-9]` quantifier. Per SOUL line 3 (KHÔNG NUỐT PILOT THÍ NGHIỆM) and Architect RESPOND V2: sk-proj- detection deferred to Python pilot vòng 2. Comment in code explicitly states this.
